---
title: "x402 on NEAR"
description: "Sell over x402 with PayRouta as your facilitator, and let any x402 client pay your payment links in USDC on NEAR, with no gas."
---

[x402](https://github.com/x402-foundation/x402) is the open standard for paying over HTTP: a server answers `402 Payment Required` with its terms, and the client pays and retries the same request. PayRouta supports x402 v2 with the `exact` scheme on NEAR.

The buyer signs one NEP-366 delegate action for a single NEP-141 `ft_transfer`. PayRouta's relayer submits it and pays the gas, so the buyer needs no NEAR, only the token.

There are two ways to use it:

- **Sell your own API or content over x402**, with PayRouta as your facilitator.
- **Let agents pay your PayRouta payment links and invoices** with any x402 client.

## PayRouta as your x402 facilitator

Run any x402 v2 resource server and send its payments to PayRouta to verify and settle. Authenticate with your PayRouta API key. A test-mode key settles on NEAR testnet, and a live key on NEAR mainnet.

| Call | Scope | What it does |
| --- | --- | --- |
| `GET /api/v1/x402/supported` | payments:read | The networks and relayer this key settles with |
| `POST /api/v1/x402/verify` | payments:write | Checks a payment against your requirements |
| `POST /api/v1/x402/settle` | payments:write | Submits the payment on NEAR and returns the transaction |
| `GET /api/v1/x402/settlements` | payments:read | Your recent x402 settlements, with explorer links |

With the x402 Foundation's TypeScript server:

```ts
import { x402ResourceServer, HTTPFacilitatorClient } from "@x402/core/server";
import { ExactNearScheme } from "@x402/near/exact/server";

const headers = { authorization: `Bearer ${process.env.PAYROUTA_API_KEY}`, "payrouta-environment": "production" };
const facilitator = new HTTPFacilitatorClient({
  url: "https://payrouta.com/api/v1/x402",
  createAuthHeaders: async () => ({ verify: headers, settle: headers, supported: headers }),
});
const server = new x402ResourceServer(facilitator).register("near:mainnet", new ExactNearScheme());
```

Price your routes in USDC on NEAR (`17208628f84f5d6ad33f0da3bbbeb27ffcb398eac501a31bd6ad2011e36133a1`), or any NEP-141 token, paid to your NEAR account. Your account must be registered with the token's storage.

A payment is refused when:

- it isn't exactly the amount, token and recipient you asked for;
- its signature or key doesn't check out, or the key isn't a full-access key;
- it's expired, or the same signed payment is sent again;
- the payer's balance is short.

PayRouta reports success only once the transfer has executed on chain.

## Payment links and invoices over x402

Any x402 client with a NEAR account can pay a live payment link or invoice in USDC on NEAR:

```
GET /api/agent/v1/x402/links/{slug}
GET /api/agent/v1/x402/invoices/{slug}
```

The first request answers `402` with a `PAYMENT-REQUIRED` header. The client signs the transfer and sends the same request again with `PAYMENT-SIGNATURE`. PayRouta settles it and answers `200` with `PAYMENT-RESPONSE` and the checkout to follow.

The USDC goes to the checkout's NEAR Intents deposit address, so you receive the invoice in whatever you settle in, and your webhooks are the same as for any payment. An agent key sent as `Authorization: Bearer pra_…` keeps the agent within its limits.

```ts
import { x402Client } from "@x402/core/client";
import { createClientNearSigner } from "@x402/near";
import { ExactNearScheme } from "@x402/near/exact/client";
import { wrapFetchWithPayment } from "@x402/fetch";

const client = new x402Client().register("near:*", new ExactNearScheme(createClientNearSigner({ accountId, secretKey })));
const pay = wrapFetchWithPayment(fetch, client);
const receipt = await pay("https://payrouta.com/api/agent/v1/x402/links/k3Fd92xQ");
```

A link's terms (`GET /api/agent/v1/links/{slug}`) list x402 among the ways to pay when it's available.

<Info>
Payment links over x402 are for live links. In test mode, use the facilitator API with a test-mode key on NEAR testnet.
</Info>
